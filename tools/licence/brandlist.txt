# Brand guard list. DRAFT written by the engineering agent on 2026-09-15; the operator reviews
# every line before 1.1.3 turns this into a build gate. Hebrew spellings in particular need a
# native eye: fix, delete, add.
#
# Format: one term per line, UTF-8. Lines starting with # are comments. Blank lines ignored.
# Matching (defined in 1.1.3): case-insensitive, whole-word, applied to file names and to text
# in every tracked file outside refs/ and docs/business/. A hit fails the build unless
# tools/licence/policy.yaml carries a dated waiver naming the path and the reason.
#
# Scope: Israeli and international retailers, marketplaces, delivery, banks, card issuers,
# payment brands, and telecom carriers a shopper meets in a checkout flow. Big-tech platform
# names (Google, Apple, Meta, Microsoft) are deliberately NOT here: they appear legitimately in
# code and docs (Apple Pay, Google Pay, Google Maps) and the guard would drown in false hits.
# The payment products are listed instead.
#
# Known collisions with ordinary vocabulary, to be handled by whole-word matching plus a waiver
# where a common noun is unavoidable: Fox, Max, Golf, Next, Wish, Bit, Cal, Bug, Ace, Delta,
# Mango, Be, Yes, Hot, Victory, Pepper, Hever, One Zero.
